# Agent 系统开发面试：从代码讲到工程取舍

这份清单用于对照代码准备回答。建议每题用“问题 → 本项目做法 → 证据 → 局限与下一步”组织答案。不要背诵未运行过的指标；本项目的离线 demo 是脚本，只有接入真实模型并完成受控评测后才能讨论模型效果。

## 一、先讲清系统边界

### 1. 你的项目解决什么问题？

它把受限的代码修复流程做成可观察、可审批、可恢复的执行系统：读取示例仓库、检索知识、提出单文件补丁、暂停等待人工决定、应用补丁并验证。价值在于执行边界和闭环，而不是一句提示词生成代码。沿 [runtime.py](../src/agent_lab/runtime.py)、[tools.py](../src/agent_lab/tools.py) 和 [storage.py](../src/agent_lab/storage.py) 讲一次具体运行。

### 2. Workflow 与 Agent 有什么区别？

Workflow 的下一步由代码控制；Agent 的下一步主要由模型根据观察选择。看 [runtime.py](../src/agent_lab/runtime.py) 的模式分支：`workflow` 固定执行检索前置后仍进入共享工具循环，不能把它描述成完全固定的端到端 DAG。离线 provider 为了可复演会按脚本选择工具；它能验证控制流，但不能作为自主规划能力的证据。选择 workflow 能减少成本与不确定性；只有动态任务分解确有价值时才增加自主性。

### 3. 为什么没有先用一个大型 Agent 框架？

本项目需要把模型消息、工具协议、状态持久化和审批暴露出来，便于学习。自行实现小循环能看清错误和状态转换。代价是重试、中断恢复、遥测和协议适配都要自己维护。生产项目可以根据团队需求选框架，仍应理解底层不变量。

### 4. 一个 Agent 循环的最小组成是什么？

目标与指令、模型调用、工具目录、执行器、观察回传、终止条件。系统还需要步数/用量预算，防止错误循环。追踪 `Provider.complete` 返回的文本块或 `tool_use`，再看执行器怎样产生 `tool_result`。模型只能提出调用，执行权限属于应用。

### 5. ReAct、Plan-and-Execute 与本项目有什么关系？

ReAct 强调行动与观察交替；Plan-and-Execute 先形成计划，再分步实施。本项目有工具循环与预设工作流，能演示这些工程结构；没有读取或存储模型私有思维链。计划应是可审查的任务与验收标准，日志记录公开的决定和行为就足够。

## 二、模型基础：知道原理，区分实现范围

### 6. Transformer 为什么适合语言模型？

自注意力根据当前表示给其他 token 分配权重，残差、归一化与前馈层逐步更新表示。自回归模型以历史 token 预测下一 token。Agent 循环建立在推理 API 之上；本项目没有训练或实现 Transformer，因此不能把 provider 适配说成大模型训练经验。

### 7. Token、上下文窗口与输出上限有什么区别？

Token 是模型分词后的计量单位；上下文窗口约束一次推理可处理的输入和输出；输出上限是本次生成可使用的最大输出预算。中文字符数与 token 数没有固定一一对应关系。[context.py](../src/agent_lab/context.py) 对消息设置序列化字符上限，不能保证等同于真实 token 上限；实际用量以 provider 返回的 usage 为准。

### 8. Temperature 越低就能消除幻觉吗？

不能。它影响采样分布，不修复知识缺失、歧义或错误证据。应通过检索、约束工具、结果验证和明确“不确定”减少错误。本项目固定 demo 不采样，重复通过并不能说明真实模型低温时稳定。

### 9. Function calling 是模型真的执行函数吗？

模型输出结构化调用意图，应用校验工具名与 JSON 参数并执行，然后回传结果。看 [providers.py](../src/agent_lab/providers.py) 与 [tools.py](../src/agent_lab/tools.py)。即使输出符合 schema，业务上仍可能越权、路径错误或基于过期内容，所以还要做权限与状态检查。

### 10. RAG、微调与提示工程如何选择？

RAG 注入可更新、可追溯的外部信息；微调调整模型行为或特定模式；提示工程组织当前任务指令。知识更新频繁或要求来源时先考虑检索，格式/行为稳定需求再评估微调。本项目实现检索与提示组织，没有 LoRA、SFT、DPO 或模型训练流程。

### 11. KV cache、prefix caching 和应用缓存相同吗？

KV cache 保存推理中注意力相关的中间状态；服务端前缀缓存可能复用相同前缀计算；应用缓存保存搜索或完整请求结果。它们的失效条件、命中条件和计费含义不同。本项目没有实现模型推理缓存；扩展检索缓存时应把知识版本、查询和权限 scope 纳入 key。

## 三、工具与代码修改

### 12. 怎样设计一个模型容易使用的工具？

使用明确名称、单一责任、有含义的参数说明、有限返回值和可恢复错误。`propose_patch(path, old_text, new_text)` 比任意 shell 命令更便于校验与审批。[tools.py](../src/agent_lab/tools.py) 的描述也是模型上下文的一部分；评测应检查是否用对工具，而不只看 schema 合法。

### 13. JSON Schema 能保证安全吗？

它能拒绝类型错误、未知字段和超长参数，不能证明业务授权或文件未被别人修改。因此还要做路径约束、文件类型白名单、审批、旧内容校验和资源限制。讲清 schema 校验与权限校验位于不同层。

### 14. 为什么先生成补丁提案，再批准写入？

提案将待写内容变成明确对象，便于展示 diff、绑定 run、记录决定并在恢复时查找。[storage.py](../src/agent_lab/storage.py) 保存提案，[tools.py](../src/agent_lab/tools.py) 应用。人工审批应绑定具体提案；批准一个旧版本不应自动允许后续任意新补丁。

### 15. 什么是 TOCTOU，项目如何处理补丁冲突？

检查旧内容与实际写入之间存在时间差，其他执行者可能已改文件。应用前再次比较当前内容与提案原始内容/摘要，发生冲突就拒绝，而不是覆盖。该机制降低普通并发冲突，但不能宣称在恶意进程并发改目录时具有完整 OS 级原子安全保证。

### 16. 重试为什么需要幂等？

调用超时可能发生在副作用已经完成之后。盲目再做一次会重复修改或重复发送。补丁 ID 与应用状态帮助识别已应用结果；外部服务还应支持幂等 key 或查状态。本项目只对受限文件修改做示范，不能据此宣称端到端 exactly-once。

### 17. 路径穿越和符号链接怎么防？

校验相对路径、禁止 `..`、拒绝越界与符号链接、限定工作根，并限制读取范围和文件大小。测试应覆盖绝对路径、嵌套 symlink 与非允许文件。[tests/test_tools.py](../tests/test_tools.py) 是证据。多租户生产系统仍需要容器或更强隔离。

### 18. 为什么 Python 语法检查不等于测试通过？

`ast.parse` 只能证明能解析，不能证明结果、边界条件或副作用正确。本项目把静态检查、确定性评测和可选容器测试分别报告。Docker 不可用时应明确标记未运行，不能用 AST 检查成功填补测试通过状态。

### 19. 为什么不在服务进程直接执行模型生成的代码？

生成代码可以读取环境变量、网络和主机文件。测试执行器应与持有模型密钥的控制进程隔离，限制网络、挂载、用户、内存、CPU、进程数和运行时间。本项目提供受限容器路径；Docker 仍不等于经过安全审计的多租户沙箱。

## 四、RAG 与引用

### 20. 本项目的检索流程是什么？

原始学习笔记 → 带来源和背景的分块 → 分词 → BM25 与词法向量两路排序 → RRF 合并 → 有界结果。看 [retrieval.py](../src/agent_lab/retrieval.py)。向量来自词法特征，不是语义 embedding；对同义改写和跨语言的泛化不能作保证。

### 21. BM25 为什么通常比字符串包含更实用？

BM25 综合词频、文档频率和长度归一化，常见词的区分力较弱，稀有标识符的区分力较强。它适合函数名、错误码和配置键；对没有词面重叠的同义表达较弱。查看分词与评分函数，理解中文切分方式如何影响召回。

### 22. RRF 是什么，为什么不用两个分数直接相加？

Reciprocal Rank Fusion 使用各检索器的名次：`score(d) = Σ 1 / (c + rank_i(d))`。不同检索分数尺度不一致，名次融合能避免简单相加时某一尺度支配结果；代价是丢失了原始分差。调节 `c` 与候选池大小应依赖检索评测。

### 23. 分块大小怎么选？

小块更精确但容易丢上下文，大块信息完整但会带入噪声。代码可按函数/类边界切，文档可按标题和段落切，并把所属文档背景加入块。不要先设一个“通用最佳 chunk size”；用真实问题的 Recall@k 和答案支持率比较。

### 24. 有引用就代表回答正确吗？

不代表。需要分别验证引用 ID 存在、引用内容与问题相关、内容实际支持结论。当前项目能提供稳定 chunk ID 和来源，未实现完整语义蕴含判定。评测最终代码状态，与回答中有没有一个 `[chunk_id]` 是不同维度。

### 25. 应怎样升级到语义检索和重排序？

加入可替换 embedding 接口、持久向量索引和模型版本字段；保留 BM25 用于精确匹配；再以 cross-encoder 或模型重排少量候选。先建立检索标注集与延迟预算，记录向量维度、距离函数及迁移策略。本项目未下载或验证这些模型。

## 五、上下文、技能与记忆

### 26. 为什么不能随便截掉历史前半部分？

工具协议要求调用与结果对应。只删 `tool_use` 或只删某个 `tool_result` 可能导致 API 拒绝，或让模型误解执行状态。[context.py](../src/agent_lab/context.py) 以完整交换组裁剪，保留初始任务和最近有效组；单组过大时应显式失败或缩小工具输出。

### 27. 裁剪与摘要各有什么代价？

裁剪便宜、可预测，但会丢旧信息；模型摘要压缩能力强，但可能漏掉或改写事实，也有额外成本。本项目采用可解释的历史裁剪，不宣称实现高质量语义压缩。持久事件留在数据库，后续可用查询工具取回，不能只依赖摘要。

### 28. Skill、Memory、RAG 有什么区别？

Skill 描述怎样做某类工作；Memory 保存跨会话经验或偏好；RAG 提供外部知识证据。它们都可能进入上下文，但来源、信任和失效机制不同。本项目分别放在 [skills.py](../src/agent_lab/skills.py)、[storage.py](../src/agent_lab/storage.py) 与 [retrieval.py](../src/agent_lab/retrieval.py)。

### 29. 渐进披露节省了什么？

启动时只给技能名和描述，相关时再读取完整说明，避免所有领域流程常驻上下文。代价是额外发现/加载步骤，错误描述还会导致漏用。工具很少时全部加载更简单；本项目只把技能元信息和正文读取分开，没有平台级海量工具搜索。

### 30. 长期记忆为什么可能有害？

错误经验、过期事实、权限串扰和敏感信息会跨会话传播。写记忆时应记录来源、作用域、时间、验证状态并支持更正和删除。本项目的 scope 键值存储是最小示例，未实现自动遗忘、冲突置信度、隐私治理或自主后台整理。

## 六、并发与持久化

### 31. 多 Agent 什么时候有收益？

独立调查方向可以并行，子上下文能减少单一窗口负担；紧密依赖的代码修改需要共享状态与协调，常会抵消收益。[runtime.py](../src/agent_lab/runtime.py) 的并行模式强调只读分析与汇总。必须在相同预算下比较延迟、用量和成功率，不能因为“角色更多”就宣称更聪明。

### 32. 同一个仓库能让几个 Agent 同时写吗？

可以设计，但需要隔离分支/worktree、任务所有权、冲突检测、合并队列和独立回归。本项目的分析并发不等于多写者开发平台。生产化时可让每个 worker 输出补丁，由单一协调者按依赖应用并验收。

### 33. Checkpoint 保存哪些内容才够恢复？

至少包括任务目标、provider/mode、消息、步骤与用量、待审批调用、提案、状态和事件。看 [storage.py](../src/agent_lab/storage.py) 与恢复测试。只保存最后一句聊天不足以判断上次副作用有没有发生；恢复前还要确认工作区与原运行绑定一致。

### 34. 崩溃发生在文件写成功但数据库未更新时怎么办？

数据库事务不能自动覆盖普通文件系统。恢复时检查当前内容是否已经等于目标内容，可把已完成应用认定为成功；若同时不等于原内容和目标内容，则需要冲突处理。更完整方案可用事务性作业记录、持久文件快照与可重放操作。

### 35. SQLite 能用于生产吗？

它适合单机、低到中等并发、部署简单的服务；并发写和跨主机任务调度存在限制。多实例应使用共享数据库、任务队列、lease/heartbeat、幂等键与明确 worker 所有权。本项目没有分布式一致性或多实例调度保证。

## 七、评测、可靠性与部署

### 36. 单元测试与 Agent eval 有什么不同？

单元测试验证确定性模块约束；Agent eval 把任务、模型、工具、环境和评分器一起运行，验收真实结果。[evals.py](../src/agent_lab/evals.py) 检查独立样例工作区、审批状态与最终算术表达式。脚本 demo 的 eval 是系统回归，不能等同于真实模型 benchmark。

### 37. pass@k 与 pass^k 怎么算？

若一次成功概率为 `p` 且尝试独立同分布，至少一次成功概率为 `1-(1-p)^k`，全部成功概率为 `p^k`。有 `n` 次样本、`c` 次成功时，常用 pass@k 无偏估计为 `1-C(n-c,k)/C(n,k)`，要求 `n≥k`。把 `c/n` 直接取幂只是带假设的估计，不等于观测到的稳定性。脚本重复不能估计真实模型随机性。

### 38. 怎样避免评测“自说自话”？

在执行前定义任务与验收，不让生成者更改隐藏测试；评分器检查最终状态和副作用，必要时结合人工复核。对失败保留轨迹和环境信息。示例用例少、公开且简单，只适合工程回归；真实求职项目还应增加不同仓库和未见缺陷。

### 39. 成功率之外还看什么？

分开记录模型调用、工具错误、审批等待、token、完成耗时、环境失败和恢复结果。线上需要成功率/延迟分位数/成本分布；不能用平均耗时掩盖长尾。报告指标时明确是否包含人工等待，是否真实计费，环境是否固定。

### 40. 预算、超时与重试怎样配合？

设置单请求超时、任务总步数、总用量与工具资源预算；有限重试只处理可恢复错误，并避免重复副作用。错误率高时要退避或中止。token 预算如果只在返回后检查可能超出一个请求，应预留下一次输出额度；严格费用预算还依赖服务端计费规则。

### 41. Prompt injection 为什么不能只靠系统提示解决？

仓库文件与检索文档可能包含伪装成指令的文字。提示可说明它们是数据，但决定安全边界的应是执行器：工具白名单、根路径限制、不可由模型自批的提案与隔离测试。当前没有注入分类器，也没有证据证明对所有注入鲁棒。

### 42. MCP 与普通 HTTP API 的关系是什么？

MCP 提供标准化的能力发现与调用约定，可通过 SDK 封装本地或远程服务。它不会自动判断业务授权，也不是 Agent 框架。[mcp_server.py](../src/agent_lab/mcp_server.py) 是可选 stdio 服务器；runtime 内部 registry 调用不经过远程 MCP client，面试时需如实说明。

### 43. 怎样把本项目改成企业服务？

先补用户认证、租户 scope 与授权；把持久记录、任务 worker 和隔离执行环境拆开；密钥留在控制面；再增加审计、监控、队列背压、取消和租约。检索结果也要按文档权限过滤，不能检索后再让模型“自觉保密”。当前本地演示不具备这些企业保障。

### 44. 你能在简历上怎么写，哪些还不能写？

可以写：“实现具备工具 schema 校验、审批式补丁应用、SQLite 恢复、知识检索和评测的代码 Agent 教学系统，提供离线演示及 Anthropic 适配。”只有自行配置模型完成实测后，才能加入模型任务数、成功率与成本。不要写“覆盖所有面试知识”“生产级安全沙箱”“自主完成大型仓库开发”或未经验证的提效百分比。

## 一个可复演的面试演示顺序

1. 展示缺陷仓库与期望行为：200 元、10% 折扣应得 180 元。
2. 启动离线运行，解释它为何适合演示 harness。
3. 在提案页面指出旧内容、新内容与审批对象；拒绝一次并展示文件未变。
4. 重新运行，批准提案，解释应用前的旧内容比较与幂等处理。
5. 展示验证结果，区分静态语法、算术 grader 与可选 Docker 测试。
6. 用数据库事件解释恢复，并说明真实模型接入、尚未实测的部分和后续评测计划。
