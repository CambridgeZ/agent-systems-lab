# RAG：检索证据而非装饰答案

本笔记为原创算法与实现说明。
阅读背景：[Introducing Contextual Retrieval](https://www.anthropic.com/research/contextual-retrieval)。

## 分块与上下文前缀

小型知识库按 Markdown 标题切分，再生成带重叠的字符窗口。标题进入索引，让
“这个函数”“该配置”之类的局部描述获得文档语境。分块 ID 由相对路径、序号与
内容哈希生成；内容改变时引用版本随之改变。项目使用人工编写的标题前缀，没有
调用模型生成 chunk context，也没有复现文章报告的效果数字。

## BM25 与词项向量

BM25 根据查询词、词频、文档长度和逆文档频率计算相关度，适合函数名、错误码、
配置项等精确匹配。第二路使用 TF-IDF 稀疏词项向量的 cosine 相似度，同样属于
词法检索。它不是语义 embedding，不能保证“退款”会匹配“退回付款”。中文二元组
仅是无需分词模型的基线，专业名词与跨语言匹配应另做评测。

## RRF 排名融合

两路分数的量纲不同，直接相加会让数值较大的排序器支配结果。RRF 对每路排名
计算 `1 / (60 + rank)` 再累加。仅把有正匹配的结果加入候选，未知查询返回空列表。
融合分数不是答案正确概率，不能把 score=0.03 展示为“3% 置信度”。

## 引用与证据支持

模型引用 `[chunk_id]` 时，该 ID 必须来自真实检索返回。引用存在只是必要条件；
还要检查被引用片段是否支持具体论断。任务事实应优先来自当前仓库，外部笔记只
提供方法知识。检索召回率、最终答案支持率和修复成功率是不同指标，需要分开记录。
